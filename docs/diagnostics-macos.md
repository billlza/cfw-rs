# CFM 整个程序无响应时采集证据

把 `scripts/collect_cfm_diagnostics.command` 单独复制到故障电脑即可；不需要安装开发工具，
也不需要把订阅、配置或密码发给排查人员。

1. 在黑屏、菜单也点不动的时候，尽量保留 CFM 进程，不要先强制退出。
2. 双击 `collect_cfm_diagnostics.command`。默认检查 `/Applications/Clash for Mac.app`。
   如果应用在其他位置，在 Terminal 中运行：
   `bash /脚本的完整路径/collect_cfm_diagnostics.command '/应用的完整路径/Clash for Mac.app'`。
3. 完成后，桌面会出现 `CFM-Diagnostics-日期时间.随机后缀.zip` 和对应目录。
4. 查看 `collection-status.txt`；它会保留失败、权限不足、进程已退出或旧版本没有新日志等情况。
5. 分享前检查文件，另附大致故障时间，以及首次启动就卡住还是运行一段时间后卡住。

脚本只读取系统版本、架构、机型、应用版本 / build / 签名检查，复制有容量上限的 CFM
诊断日志，并对匹配的 GUI 进程采样两秒调用栈。它不退出程序、不修改网络或配置、不采样
Packet Tunnel / 代理服务，也不自动上传。

日志已做凭据脱敏，但仍可能含目标域名、节点名称；系统生成的调用栈可能含本地路径。
不要把包含其他私人资料的文件夹、订阅文件或整个应用配置目录一起打包。

旧版 40070 缺少新的持久日志，脚本仍可以获取正在卡住的主进程调用栈。这对于区分
文件锁、Keychain、系统调用、原生 UI 事件循环和其他阻塞尤其有用。
健康机器的采样只能验证采集器可用，不能替代故障机器的样本。
