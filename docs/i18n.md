# CFM 国际化

语言入口位于 **Settings → Appearance → Language**（设置 → 外观 → 语言）。
支持跟随系统、简体中文、繁體中文、English、日本語。具体语言使用各自的原文名称，便于切回。
语言选择保存成功后更新界面与原生菜单，不调用内核启动、停止、代理切换或网络配置写入。

## 实现

- `apps/cfw-tauri-shell/ui/src/i18n.js` 提供语言选择、英文回退、具名参数替换及本地化日期格式。
  英文原文作为消息键；四份 JSON 位于同目录的 `locales/`。所有资源随应用打包，不向翻译服务发送文本。
- 页面、设置、弹窗、状态标签、操作反馈和独立启动恢复界面使用同一套消息。
  只翻译产品拥有的显示文字；节点和配置文件名称、规则内容、协议值、路径、错误代码及引擎原始诊断保留原文。
- Rust 原生菜单使用相同 JSON。语言状态由应用管理，菜单动作 ID 与路由匹配值保持不变。
  macOS 语言偏好读取和词库准备在后台执行，主线程仅更新菜单；菜单栏代理列表更新沿用现有只读路径。
- “跟随系统”使用 macOS 的有序语言偏好。明确的 Hans/Hant 优先于地区；TW、HK、MO 使用繁体，
  其他无脚本标记的中文使用简体。依次寻找支持的语言，全部不支持时使用英文。
- 翻译结果为纯文本。HTML 渲染处对整个结果转义，参数内容不会再次作为消息模板解释。
  缺少必需参数会显式报错；缺少消息的英文回退不替代构建中的词库完整性检查。
- 设置工具栏支持按钮换行，避免日语长文案在最小 850 × 603 窗口中被挤成竖排。

## 偏好存储

`UiPreferences.language` 是封闭枚举：`system`、`en`、`zh-Hans`、`zh-Hant`、`ja`。
偏好文件使用 schema 2。读取原来的 schema 1 时，先验证其完整字段和规范 JSON，再补入 `system`；
单纯读取不改写旧文件，首次保存才写入新格式，其他设置保留。
损坏 JSON、未知字段、未知语言和不支持的版本仍被拒绝。

旧 40072 无法读取保存后的 schema 2。后续安装验收及回退方案需要保留原偏好文件；
不能把读取兼容性表述成旧二进制也能识别新格式。本轮未修改本机正在使用的偏好文件。

## 增加或修改翻译

1. 在原文调用点和 `locales/en.json` 中定义消息，再补齐另外三个词库。
2. 动态文本使用完整消息和具名参数；不要拼接英语单复数后缀，也不要对整个 DOM 或用户名称做自动翻译。
3. 对新增语言同时扩展前端选项、Rust `UiLanguage`、系统语言匹配和原生词库选择，并补对应测试。
4. 运行 UI 构建与测试、相关 Rust 测试和严格 Clippy；涉及布局的更改检查实际最小窗口尺寸。

`ui/tests/i18n.test.mjs` 检查四语言键集合、参数一致性、静态调用覆盖、系统语言匹配、转义和状态标签。
页面集成测试逐页切换四种语言，验证运行身份不变、保存失败恢复原语言且不发送网络变更命令。
启动测试执行独立的已打包脚本，即使主界面启动失败，也能显示所选语言的恢复操作。
