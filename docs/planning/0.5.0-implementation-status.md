  feature in the existing host, with a native menu entry and shortcut.

  Proxy and TUN states; unknown/failure and non-ready states remain explicit.

  the existing Tauri commands, including their queue, snapshot-sensitive enables,
  owned stops, retirement/profile/capability/authorization and maintenance rules.

  command ownership after window close, and explicit same-mode Retry/Continue
  Approval. An explicit retry still awaiting approval uses the existing system
  settings navigation; no automatic approval or permission change is introduced.
- Versioned C ABI with bounded frames, main-thread ownership, one pending delivery,
  session isolation, cancellation and exactly-once close callbacks.
- English, Simplified/Traditional Chinese and Japanese resources; native glass
  toolbar control on supported systems and standard accessibility/OS fallback.
- The four relevant Rust files from the separately tested 0.4 startup/read/quit
  repair, so the internal snapshot read cannot retrigger failed reconciliation.

The host currently still uses Tauri for application composition and the existing
control surface. This is not the completed standalone SwiftUI replacement, full
90-command parity, a newly signed build, or an installed VPN validation.

## Dependency and VPN review

Official checks on 2026-09-22 still identify [Rust 1.98.1](https://blog.rust-lang.org/2026/09/03/Rust-1.98.1/)
and [sing-box 1.14.1](https://github.com/SagerNet/sing-box/releases/tag/v1.14.1)
as current stable releases, matching the existing pins. No compiler, engine,
dependency lock or engine patch has been updated in this UI change.

The available [saphyr-parser 0.1.0](https://crates.io/crates/saphyr-parser/0.1.0)
changes plain empty-node events from `"~"` to `""` ([upstream change](https://github.com/saphyr-rs/saphyr/pull/129)).
The current null-value path already handles both, but mapping keys retain scalar
text and need an explicit compatibility decision. Upgrade separately, retaining
alias/anchor/tag/multidocument rejection and validating exact depth/event limits.
This check covers these three versions, not the entire transitive dependency graph.

Current schema/import and Apple build support do not establish OpenVPN/OpenConnect
support merely because sing-box provides those endpoints. Their schemas,
credentials, interactive authentication, backend build, DNS/routes and real-server
interoperability need separate implementation and packet evidence. Preserve current
WireGuard, UDP/QUIC and IPv6 behavior through UI migration first.
