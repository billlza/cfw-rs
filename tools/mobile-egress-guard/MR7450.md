# MR7450-100EUS feasibility record (2026-10-21)

This note separates observed public facts from assumptions. **No firmware is
flashed, no debug shell is entered and no M7 Pro admin command is executed.**

## Device and source identity

- User-observed display: NETGEAR MR7450-100EUS, Software Update screen reports
  MR7450-100EUS_01.15. A screen saying "No update available" does not prove
  that the device's kernel or root filesystem matches another user's bytes.
- A 2026-09-23 NETGEAR Community report for the same model and software label
  also reports NTGX75_10.04.43.01. Treat that as a **candidate** internal
  firmware version, not a verified hash of this device's image.
- NETGEAR's public GPL/LGPL index lists MR7450 firmware 10.01.14.00. Its
  associated old OSS archive URL has been observed returning HTTP 404. No
  current-version source package or complete flash image has been verified.
- A request for publicly distributable corresponding sources, any official
  recovery image and supported application execution mechanisms was sent to
  NETGEAR on 2026-10-21. No answer is assumed.

## Supported device features worth separating

The MR7400/MR7450/MR7500 official user manual documents:

- Settings > Advanced > Data Usage: view data usage, reset the counter,
  configure a counter reset date and data-plan limit. The manual does **not**
  prove that exceeding that limit disconnects all traffic.
- Settings > Advanced > Mobile Router Setup: IP passthrough is supported over
  USB or Ethernet. Most mobile carriers assign private WWAN addresses.
- Settings > Advanced > Other: VPN passthrough is documented. This is **not**
  an onboard VPN server, VPN client SDK, or general executable environment.
- Ethernet 2.5GbE and USB tethering are available physical gateway links.

The NETGEAR Insight compatibility matrix includes MR7450-100EUS at software/
PRI 01.15. Public product information documents remote Ethernet control in
Insight, not a programmable reverse-tunnel service or complete public device API.

## Engineering dependencies

Desired end state: the M7 Pro itself initiates an authenticated outbound link
to a public VPS, with its own SIM as egress, while the Mac is optional.

Before building an on-device Agent, identify through legitimate **offline**
materials:
1. Exact firmware build and update container format, kernel architecture and
   root filesystem after authenticated source acquisition.
2. Official developer execution capability, application deployment and durable
   startup registration, if any. An OSS source archive is not such permission.
3. Secure Boot and signature checks for this hardware, not a similarly named
   R7450 router. No third-party router image is presumed compatible.
4. Official recovery path and evidence the cellular modem, Ethernet and Wi-Fi
   remain functional after any software change.

If no trustworthy on-device execution path is available, use an isolated
low-power gateway or Mac prototype linked by Ethernet/USB to M7 Pro. Neither
assumption is evidence that M7 Pro firmware has been bypassed.

## Carrier bandwidth and anti-abuse

Serving downloads to remote users consumes *outbound* bytes on the UK mobile
connection. The UK mobile **uplink**, not the advertised 5G download speed,
can therefore be the bottleneck. Account for VPS transfer charges, latency,
carrier policy, data quotas, outages and IP changes in capacity tests.

Enforcement design: authenticated individual users at a VPS, a reverse
connection from the UK exit, default deny on missing/unknown authority, active
hard quotas on the VPS, independent carrier-usage budget and a global emergency
disconnect. A Mac observer is a second source of visibility and cannot provide
this guarantee while offline. It should never inspect private content by
default or promise automatic classification of a user's lawful conduct.

Before enabling public or commercial access, obtain individual advice on
Student visa restrictions, SIM-plan resale/tethering terms, relevant UK
communications rules, incident response and data minimisation.
